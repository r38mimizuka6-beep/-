# 使い方（実データでの運用手順）

**どこかのサイトにアップロードするのではありません。** このツールは自分のPCの中で
動きます。ファイルは、PC上で開いたダッシュボードの「アップロード欄」に
ドラッグ＆ドロップするだけです。データは一切外に出ません。

---

## 1. 最初の1回だけ：準備

### 1-1. Python を入れる（すでに入っていれば飛ばす）

- Windows: [python.org](https://www.python.org/downloads/windows/) から最新版を入れる。
  インストール画面で **「Add python.exe to PATH」にチェック**（これを忘れると起動しません）
- Mac: [python.org](https://www.python.org/downloads/macos/) から入れる

> 会社のPCでインストールが制限されている場合は、情報システム部門に
> 「Python と pip を使いたい」と相談してください。

### 1-2. ツール一式をPCに置く

GitHubの `shoken_analyzer` フォルダを丸ごとダウンロードし、
デスクトップなど好きな場所に置きます（例: `C:\\Users\\自分\\Desktop\\shoken_analyzer`）。

### 1-3. 起動する

| OS | やること |
|---|---|
| Windows | フォルダの中の **`start.bat`** をダブルクリック |
| Mac | フォルダの中の **`start.command`** をダブルクリック |

初回だけ数分かかります（必要なライブラリを入れています）。
終わるとブラウザが開き、ダッシュボードが表示されます。

> Macで「開発元を確認できないため開けません」と出たら、
> `start.command` を右クリック →「開く」→「開く」。

2回目からは、同じファイルをダブルクリックするだけで数秒で開きます。

---

## 2. どのファイルを、どこに入れるか

ダッシュボードの上にタブが5つ並んでいます。**上から順に使います。**

### ① 蓄積データ タブ（最初に1回。以降は週次で追加）

| 入れるもの | 置き場所（画面の欄） | 形式 |
|---|---|---|
| **既存5店の週次IDPOS** | 「週次IDPOS」 | CSV（システムからのエクスポートそのまま） |
| **既存5店の週次 売上在庫（粗利）** | 「週次 売上在庫（粗利）」 | CSV（そのまま） |
| **商圏レポートExcel（5店分）** | 「商圏レポートExcelから商圏マスタを作る」 | .xlsx（1店舗=1ブック） |

商圏レポートExcelを入れて「Excelから項目を取り出す」を押すと、表が出ます。
**ここで2か所だけ直してください。**

1. `store_id` を **IDPOSの「店舗CD」と完全に同じ**にする（`0785` のように先頭ゼロも）
2. `open_date` に**業態転換オープン日**を入れる（日が不明なら `2026-04` のように月まででOK）

直したら「既存店の商圏マスタとして登録する」を押します。

> 競合・周辺施設・来店手段は商圏レポートに入っていません。
> 空欄のままでも動きます（その項目が類似度計算から外れるだけ）。
> 埋めたい場合は⑤タブへ。

入れ終わると、下に **「入っているもの」** が表示されます。
店舗ごとに何週分あるかが色で分かるので、ここで抜けがないか確認してください。

### ② 新店を判定 タブ（レポートを出すとき）

| 入れるもの | 置き場所 |
|---|---|
| **町田店の商圏レポートExcel** | 「新店の商圏情報」（上の選択を「商圏レポートExcel」に） |

出てきた表で `store_id` と `open_date`（オープン予定日）を直し、
**「レポートを出力」** を押します。

出てくるもの:
- 画面に予測表・精度グラフ・立ち上がりカーブ
- **HTMLレポート** / **Excelレポート** / **配布用HTMLダッシュボード** のダウンロードボタン
- 予測は自動保存され、③タブでの答え合わせに使われます

### ③ 予実検証 タブ（開店後）

| 入れるもの | 置き場所 |
|---|---|
| **町田店の週次IDPOS（開店後）** | 「新店IDPOS」 |
| **町田店の週次 売上在庫** | 「新店の売上在庫」 |

「突き合わせる」を押すと、予測と実績の差が出ます。
開店直後2週は自動で除外、4週未満は「判定保留」になります。

### ④ 運用の状態 タブ

自動で直したものと、人が決めることが並びます。
「採用」「見送り」を押すと記録されます。

### ⑤ 検索データ タブ（任意）

店舗名を入れると検索クエリが出ます。地図や検索結果を見て、
競合数・周辺施設数などを表に書き込み、「追記する」を押します。

> **件数は必ず同じ半径で数えてください。** 店によって半径が違うと
> 類似度の計算が壊れます。

## 2-B. エクスポートの抽出項目（軽くするために）

抽出項目を減らすとファイルが軽くなり、出力も速くなります。
**使っているのは下の項目だけ**です。これ以外は外して構いません。

### 売上在庫（粗利）

| 区分 | 項目 | 要否 |
|---|---|---|
| キー | 年週 / 店舗CD / 店舗名 | **必須** |
| キー | ディビジョン名 / ライン名 / 部門名 / カテゴリー名 / サブカテゴリー名 / セグメント名 | **必須**（見たい粒度まで） |
| 数値 | **販売荒利高** | **必須** |
| 数値 | **販売荒利率** | 下の「売上金額(税抜)」が無いなら必須 |
| 数値 | 売上金額(税抜) | 任意。あればこちらを優先（荒利率より正確） |
| — | 売上数量 / 在庫数量 / 売価在庫高 / POS値下◯ / 廃棄◯ / 売変◯ / システムロス / ロス率 | **不要**（外してよい） |

数値は **2項目だけ**で足ります。

- 最小構成A：`販売荒利高` ＋ `販売荒利率`
- 最小構成B：`販売荒利高` ＋ `売上金額(税抜)` ← **推奨**

Bを勧める理由は、上位階層の粗利率を売上で加重平均するのに売上の金額が要るためです。
Aの場合は「荒利高 ÷ 荒利率」で売上を逆算しますが、荒利率は小数2桁に丸めて
出力されるため、わずかに誤差が乗ります。Bなら丸めの影響を受けません。

> 売上数量は**IDPOS側**から取るので、売上在庫側には要りません。

### IDPOS

| 区分 | 項目 | 要否 |
|---|---|---|
| キー | 年週 / 店舗CD / 店舗 | **必須** |
| キー | ディビジョン / ライン / 部門 / カテゴリー / サブカテゴリー / セグメント | **必須**（見たい粒度まで） |
| 数値 | 売上数量 / PI値 | **必須**（客数の復元に使う） |
| 区分 | 顧客種類 / 年代 | **必須**（年代構成に使う） |
| 数値 | 売上税抜金額 / POS客数 / ID客数 | 任意（単価と買上率の内訳に使う） |

### さらに軽くする

| やること | 効き方 |
|---|---|
| **ディビジョン＝低温 で絞ってエクスポート** | 最も効きます。低温以外は読み込み時に捨てているので、出す意味がありません |
| セグメントまで出さず、**サブカテゴリーまで**にする | 行数が数分の1になります。納豆→小粒のような粒度で足りるならこれで十分です |
| 合計行・小計行を出さない | 読み込み時に捨てていますが、ファイルが軽くなります |

### 列名が違うとき

エクスポートの見出しがここと違っても、`config\metrics.yaml` の
`idpos.pi_file.columns` と `idpos.margin_file.columns` を実際の見出しに
書き換えれば動きます。取り込み時に「粗利ファイルに無い列」と警告が出たら、
その警告に出ている名前を直してください。

単位が千円でなく円の場合は、同じ箇所の `gross_profit_scale` を `1000` から
`1` に変えてください（売上金額が千円なら `sales_amount_scale` を `1000` に）。

---

## 3. 毎週の運用

1. IDPOSと売上在庫の**最新週**をエクスポート
2. ダッシュボードを起動 → **①タブに追加**（同じファイルを入れても二重にはなりません）
3. 開店後なら **③タブで突き合わせ**
4. **④タブ**で提案を確認

週が増えるほど「ブレの範囲」が狭まり、判定が確定していきます。

---

## 4. 最初の実行で必ず見てほしい警告

①タブや②タブの下に黄色い帯で警告が出ます。特にこの3つ:

| 警告 | 意味 | 対応 |
|---|---|---|
| **小計・合計とみられる行を◯件除外しました** | 「年代=計」などの小計行を捨てた | 件数が多すぎないか確認。必要な明細まで消えていないか |
| **復元した客数が◯%食い違います** | PI値の分母が明細ごとに違う可能性 | 出た場合は連絡してください |
| **商圏マスタにあってIDPOSに無い店舗CD** | store_id が一致していない | 先頭ゼロを含めて合わせる |

## 5. 配るとき

②タブの **「このダッシュボードをHTMLで書き出す」** で1枚のHTMLが落ちます。
Python不要・オフラインで開けるので、上長や他部署にはこれを渡してください。

**ただし実績由来の数値が埋め込まれます。社外には出さないでください。**

## 6. うまくいかないとき

まず **`起動できないとき.txt`**（`shoken_analyzer` フォルダの中）を開いてください。
起動まわりの症状はすべてそこに書いてあります。

| 症状 | 原因と対応 |
|---|---|
| `start.bat` で文字化けしたエラーが大量に出る | 古い `start.bat`。ZIPをダウンロードし直す（`data` と `output` は先に退避） |
| `'env' は、内部コマンドまたは…` と出る | 同上。改行コードがLFのままの古い版 |
| `start.bat` が一瞬で閉じる | Python未インストール、またはPATH未設定。1-1をやり直す |
| `[ERROR] Python was not found` | 1-1 をやり直す。インストーラで **Add python.exe to PATH** に必ずチェック |
| `[ERROR] app\dashboard.py was not found` | `start.bat` だけを別の場所にコピーしている。フォルダごと使う |
| `[ERROR] Could not create the .venv folder` | OneDrive配下だと失敗することがある。`C:\` 直下などに移してから再実行 |
| ライブラリのインストールに失敗 | 社内ネットワークの制限。情報システム部門に `pip` の利用を相談 |
| 「ディビジョン『低温』の行がありません」 | エクスポート時に低温以外だけを出している。または列名が違う。`config/metrics.yaml` の `idpos` を確認 |
| 文字化けする | `config/metrics.yaml` の `idpos.encoding` を `utf-8-sig` に変える |
| カテゴリーが少ない | `config/metrics.yaml` の `target_categories` の `aliases` に実際の表記を追記 |

### どうしても起動しないとき（手動起動）

`shoken_analyzer` フォルダをエクスプローラで開き、アドレスバーに `cmd` と入力して Enter。
開いた黒い画面に、以下を1行ずつ貼り付けて実行します。

```
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m streamlit run app/dashboard.py
```

Macの場合はフォルダを右クリック →「フォルダに新規ターミナル」で開き、以下を実行します。

```
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python -m streamlit run app/dashboard.py
```

ここで出たエラー文をそのまま共有いただければ、原因を特定できます。
