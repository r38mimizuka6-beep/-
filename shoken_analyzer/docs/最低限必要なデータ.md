# 数字を出すのに最低限必要なデータ

実測しました。サンプルデータで既存店数と週数を変えて、何セルの数字が出るかを数えた結果です。

| 既存店数 | 週数 | 結果 |
|---|---|---|
| 1店 | — | **停止**（最低2件必要） |
| 2店 | 4週 | 90 / 90 セル |
| 2店 | 8週 | **135 / 135 セル** |
| 3店 | 8週 | 135 / 135 セル |
| 5店 | 20週 | 135 / 135 セル |
| 5店 | 20週（open_date なし） | 135 / 135 セル |

**結論：IDPOSと店舗CDが一致する既存店が2店あれば、数字は出ます。**
週数と open_date は、数字が「出るかどうか」ではなく「当たるかどうか」に効きます。

---

## 必須（これが欠けると1つも数字が出ない）

### 1. 商圏マスタの `store_id` が、IDPOSの `店舗CD` と一致していること

**今回の出力が全て「—」だった原因はこれです。**

```
商圏マスタの store_id : 西友　河辺店様, 西友　浦安店様     ← 店舗名
IDPOSの店舗CD        : 0785, 0803, 0810, 0819, 0821    ← コード
両方に揃っている既存店が 0店
```

**ファイル名の先頭に店舗CDを付ければ自動で入ります。**

```
0785_トライアル西友花小金井店.xlsx   → store_id = 0785
0785_花小金井.xlsx                 → store_id = 0785
```

商圏レポートExcel・検索データExcelの両方で効きます。先頭ゼロは落ちません。
西暦に見える4桁（`2024_...`）や末尾の日付（`..._20250401.xlsx`）は
店舗CDとして扱いません。

ファイル名に付けられない場合は、表で直接 `store_id` を書き換えてください。
①蓄積データ タブにIDPOSの店舗CD一覧を出し、一致していなければ
登録前に赤字で警告します。

### 2. 既存店が2店以上

1店だと停止します。類似店法は「似ている店の実績を使う」手法なので、
比較対象が要ります。実用上は3店以上を推奨します。

### 3. IDPOS に必要な列

| 列 | 用途 |
|---|---|
| 年週 / 店舗CD | 突き合わせの鍵 |
| ディビジョン〜カテゴリー（見たい粒度まで） | 集計単位 |
| **売上数量 / PI値** | この2つから店全体の客数を逆算しています |
| 顧客種類 / 年代 | 年代構成 |

### 4. 売上在庫に必要な列

| 列 | 用途 |
|---|---|
| 年週 / 店舗CD / 階層名 | 突き合わせの鍵 |
| **販売荒利高** | 粗利 |
| **販売荒利率 または 売上金額(税抜)** | どちらか一方。上位階層の粗利率を売上で加重するのに使う |

## 数字は出るが、当たらない（強く推奨）

### 5. 各店 8週以上の週次IDPOS

今回は**中央値6週**でした。8週未満だと「水準が信用できない」と判定され、
今回は260件の店舗×単位がその扱いになっています。

週を増やしても**店舗数は増えない**ので予測の土台は強くなりませんが、
各店の水準のブレは小さくなります。

### 6. `open_date`（開店・改装オープン日）

今回は未入力でした。開店直後の数週は需要が跳ねるため、転換時期が店ごとに
違うと、**開店効果が「その店の実力」として水準に混ざります。**
転換店なら転換日を入れてください。

**置き場所は商圏マスタでも検索データでもどちらでも構いません。**
検索データ側に `open_date` 列（`2024-03-15` の形）があれば、
商圏マスタに無くても使われます。検索データExcelの商圏サマリーに
「オープン日 | 2024年3月15日」の行を足しても読み取ります。

### 7. 商圏マスタの軸変数に、店舗間のばらつきがあること

今回は14変数が「ばらつきが無い」として類似度計算から外れました。
店が2店しか入っておらず、しかも値が同じか空だったためです。
**全店で同じ値の変数は、似ているかどうかの判断に使えません**（情報量がゼロ）。

> この確認中に、関連する不具合を見つけて直しました。同じ値が5つ並んでも
> 標準偏差がちょうど0にならず `3.1e-17` になる場合があり、これを
> 「ばらつきあり」と誤判定していました。丸め誤差を標準偏差で割るため
> z値が10^16のオーダーになり、**その1変数だけで類似店が決まってしまう**
> 状態でした。相対誤差で判定するよう修正し、テストで固定しています。

## 今回の出力に対して、順番にやること

1. **商圏マスタを登録し直す**。ファイル名に店舗CDが付いていれば
   `store_id` に自動で入ります。すでに蓄積ずみのマスタは店舗名のままなので、
   ①蓄積データ タブで取り込み直してください
2. 全5店ぶんの商圏レポートExcelを登録する（今は2店ぶんしか入っていません）
3. `open_date` を入れる（検索データ側で構いません）
4. IDPOSを8週以上貯める（今は6週。6週でも数字は出ますが精度の判定が甘くなります）
5. 余力があれば、⑤検索データで軸3（移動手段）を埋める

1番だけで「—」は解消します。2〜4で精度が上がり、5で類似店の選び方が変わります。

## 参考：今回の出力に出ていた他の警告

| 警告 | 意味 | 対応 |
|---|---|---|
| `'販売荒利高(千円)' は '販売荒利高(円)' として読みました` | 列名と単位を自動で解釈した。**正常** | 不要 |
| `年代が取れていない売上が最大57%` | 非会員ぶん。年代構成は分かる分だけの比率 | 不要（そういうもの） |
| `転換前のIDPOSが残っておらず使えません` | 転換前後法は使えない | 次の転換店に向けて今週から保存 |
