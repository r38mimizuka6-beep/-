# 重い・固まるときの対処

## 何が起きていたか（修正済み）

画面が固まる原因は3つありました。いずれも修正済みです。
**ZIPを取り直してください。**

| 原因 | 実測（98MB・120万行のIDPOS 1本） |
|---|---|
| 階層名の連結を行ごとにPythonで回していた | レポート1本 **112秒 → 17秒** |
| 蓄積状況の確認で毎回全ファイルを全列読んでいた | 画面操作ごと **6.4秒 → 0.01秒** |
| 使わない列まで読み込んでいた | ピークメモリ **3.6GB → 1.8GB** |

とくに1つ目が致命的で、112秒のうち101秒をここで使っていました。
pandas の `DataFrame.agg(..., axis=1)` が行ごとにPythonを呼ぶためです。

蓄積状況は `warehouse/.peek_cache.json` に記録し、ファイルが増えたときだけ
読み直します。画面のタブを切り替えるたびに全ファイルを読むことはもうありません。

## 現在の目安

| データ量 | レポート1本 | ピークメモリ |
|---|---|---|
| 98MB / 120万行 | 約17秒 | 約1.8GB |
| 300MB / 360万行 | 約50秒 | 約5GB |

**メモリは搭載量の半分を超えないようにしてください。** 超えるとWindowsが
ディスクに退避しはじめ、見かけ上フリーズします。8GBのPCなら合計300MB、
16GBなら合計800MBが目安です。

蓄積が800MBを超えると、①蓄積データ タブに警告が出ます。

## それでも重いとき：エクスポートを軽くする

**効果が大きい順です。** 項目を減らすより、行数を減らすほうがずっと効きます。

### 1. ディビジョン＝低温 で絞ってエクスポートする（最大の効果）

低温以外は読み込んだ直後に捨てています。出す意味がありません。
全ディビジョンを出していた場合、これだけで数分の1になります。

### 2. セグメントまで出さず、サブカテゴリーまでにする

行数が数分の1〜十数分の1になります。
「和日配 → 納豆」の粒度で足りるなら、セグメントは不要です。

セグメントまで見たくなったら、そのときだけ出し直せば済みます。

### 3. 不要な抽出項目を外す

売上在庫で実際に使うのは **販売荒利高** と、**販売荒利率 か 売上金額(税抜)**
のどちらか1つだけです。在庫・値下・廃棄・売変・ロスは読んでいません。

詳細は [使い方.md の 2-B](使い方.md) にあります。

### 4. 古い週を外す

52週より前のデータは、水準の計算にほとんど効きません。
`warehouse/idpos/` から古いファイルを削除すれば、その分軽くなります。
（削除後、次回の起動で蓄積状況は自動的に再計算されます）

---

## 操作のコツ

- **レポート出力のボタンは1回だけ押す。** 計算中に他のタブを触ると、
  そのぶん再計算が走ります
- **出力が終わるまで待つ。** 進行中はスピナーが回っています
- 一度出したレポートは `output/` に残るので、**同じ内容を見るだけなら
  再出力せずHTMLを開いてください**

---

## 本当に固まってしまったら

1. 黒い画面（または `stop_dashboard.vbs`）でサーバーを止める
2. `open_dashboard.vbs` で開き直す

蓄積したデータは `warehouse/` に残っているので、入れ直しは不要です。
