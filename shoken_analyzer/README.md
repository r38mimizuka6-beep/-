# 類似店判定レポート自動生成ツール（shoken_analyzer）

新店の商圏情報を入れると、既存5店舗の中から類似店を選び、初期棚割の出発点になる
レポート（HTML / Excel）を自動で出力します。

## このツールがやらないこと（重要）

**「商圏→売上構成比」の予測モデルは作りません。**
既存店が5店なのに対して商圏変数は数十あるため、回帰でもGBMでも必ず過学習します。
代わりに、次の3つだけを出します。

1. **類似店法** … 新店の商圏に近い既存店を1〜2店選び、その実績値をそのまま出発点にする
2. **差の方向** … 店舗間の商圏差と構成比差の符号が、何店・何ペアで揃うかを数える
3. **範囲内チェック** … 新店の各指標が既存5店の最小〜最大に収まるかを判定する

レポートの数値はすべて「既存店で実際に起きたこと」であって、予測値ではありません。
レポート本文にもその旨が出力されます。

## セットアップ

```bash
pip install -r requirements.txt
```

必要なのは pandas / numpy / openpyxl / PyYAML だけです。

## まず動かしてみる

```bash
python run_report.py demo
```

同梱のダミーデータ（都市部4店＋郊外1店＋新店1店）でレポートが出ます。

- `output/demo_report.html`
- `output/demo_report.xlsx`

## 入力テンプレートを作る

```bash
python run_report.py template --out data/templates
```

| ファイル | 中身 |
|---|---|
| `00_項目定義.csv` | 各列の意味・取得元・どの軸で使うか |
| `01_store_master.csv` | 既存店マスタ（1行=1店舗、5行） |
| `02_new_store.csv` | 新店（1行） |
| `03_sales_mix.csv` | 店舗×カテゴリの売上構成比・粗利（縦持ち） |
| `04_member_mix.csv` | 店舗×性別年代の会員構成比（縦持ち） |
| `README_入力テンプレート.txt` | 埋め方の説明 |

## 商圏レポートのExcelから自動で埋める

市販の商圏レポート（1店舗=1ブック、JICFS消費推計つき）がある場合、
「A. 商圏の人」に当たる約30項目は自動で抽出できます。

```bash
python run_report.py extract \
    --xlsx 既存店A.xlsx 既存店B.xlsx 既存店C.xlsx 既存店D.xlsx 既存店E.xlsx \
    --out data/extracted_master.csv \
    --demand-out data/category_demand.csv
```

- 自動で入る: 人口・年齢構成・世帯構成・住居形態・年収・昼夜間人口・事業所数など
- **手入力が必要**: 来店手段、駐車場、最寄駅、競合、周辺施設、自店の条件（B〜E）

セル番地は `config/extract_shoken_report.yaml` にあるので、レポートの版が変わっても
コードは触らず設定だけ直せば動きます。

`--demand-out` で出る `category_demand.csv` は、商圏のJICFS中分類別の消費推計
（1人当たり金額・商圏指数）です。これは **自店の売上構成比ではなく商圏側の需要** なので、
類似度の説明変数には使わず、棚割提案の裏付け・反証にだけ使ってください。

## レポートを出す

```bash
python run_report.py report \
    --master data/my_master.csv \
    --new    data/my_new_store.csv \
    --sales  data/my_sales_mix.csv \
    --member data/my_member_mix.csv \
    --out    output/新店レポート.html \
    --excel  output/新店レポート.xlsx
```

軸の重みを変えて感度を見る:

```bash
python run_report.py report ... --weight daynight=2.0 --weight mobility=0.5
```

類似店を3店にする:

```bash
python run_report.py report ... --top 3
```

## レポートの中身

| 章 | 内容 |
|---|---|
| 1 | 新店の商圏サマリ（3軸での位置づけ、都市部／郊外の判定とその内訳） |
| 2 | 類似店ランキング・類似度・選定理由（軸ごとの距離と、残っている差） |
| 3 | 範囲外の指標と信頼度の注意書き |
| 4 | 商圏差とカテゴリ構成比差の方向性の仮説（同傾向の店舗数つき） |
| 4-2 | 会員の性別年代構成比と商圏年齢構成のズレ |
| 5 | 初期棚割の提案（カテゴリ別の構成比レンジと増減の方向） |
| 6 | 開店後にIDPOSで検証・修正すべき項目のチェックリスト |

### 類似度の3軸

都市部の中の違いを分ける3軸で距離を測ります。重みは変更可能です。

| 軸 | 内容 | 主な変数 |
|---|---|---|
| 軸1 昼夜人口比 | 住宅地型 ⇔ オフィス・繁華街型 | 昼夜間人口比、従業者数/夜間人口、生徒学生数/夜間人口 |
| 軸2 世帯構成 | 単身 ⇔ 子育て ⇔ 高齢 | 単身世帯比率、6歳未満同居世帯比率、65歳以上同居世帯比率、平均世帯人員 |
| 軸3 移動手段 | 徒歩・自転車 ⇔ 駅利用 ⇔ 車 | 徒歩・自転車比率、鉄道比率、車比率、駐車台数、最寄駅距離 |

距離は、既存5店の平均と標準偏差で標準化したうえでの重み付きユークリッド距離です。
既存5店でばらつきが無い変数は自動で除外され、レポートに明示されます。

### 方向性分析で気をつけていること

5店舗では、変数同士がほとんど同じ動きをします（共線性）。そのまま全変数を並べると、
同じ1つの事実を何十回も数えて「根拠が山ほどある」ように見えてしまいます。
そこで本ツールは、

- 5店舗での相関が0.95以上の変数をまとめ、代表1本だけをレポートに出す
- まとめられた変数は「同じ動き」として併記する（どれが効いているかは判別不能と明記）
- 符号が完全にランダムだった場合に何件ヒットするか（期待値）を計算して併記する

を行います。抽出件数がこの期待値に近いなら、その分は中身のない当たりです。

### 郊外店が1店しかない件

新店が郊外寄りと判定された場合、レポートに警告が出ます。
郊外店は「郊外という立地の効果」と「その1店の個性」を切り分けられないため、
郊外 vs 都市部の構成比差はカテゴリの当たりをつける材料としてのみ扱ってください。

## 実データへの差し替え

実データの項目名が決まったら、`config/columns.yaml` の `source:` を書き換えるだけです。
コードは変更不要です。

```yaml
  - {key: pop_total, source: 商圏内人口_総数, label: 人口総数, group: people, kind: scale, enabled: true}
                     ^^^^^^^^^^^^^^^^^^^ ここを実データの列名にする
```

- 使わない項目は `enabled: false`
- 項目を足す場合は `variables:` に1行追加し、必要なら `axes:` にキーを入れる
- 都市部／郊外の閾値は `urban_rural.rules` の `rural_at` / `urban_at`
- 軸の既定の重みは `axes.<軸名>.weight`
- 会員の年代区分を変えたら `member_compare_buckets` と `age_cmp_*` の両方を直す

未入力の項目があっても動きます。その項目は類似度・範囲チェックから除外され、
レポートに「未入力」として出ます。

## 既知の制約

- 既存店が5店である限り、本ツールの出力は仮説です。有意性の検定はしていません。
- IDPOS会員に居住地が紐づいていないため、「商圏外からの来店」と「商圏内で来ていない層」は
  分離できません。会員ズレの数値にはこの2つが混ざっています。
- 商圏定義（自転車10分圏など）が店舗間で揃っていないと、距離計算の結果は意味を持ちません。
  テンプレートの `商圏定義` 欄で揃えてください。
- 売場面積が大きく違う店を類似店に選んだ場合、構成比はそのまま使えません。
  絶対額ベースでの再検討が必要です（レポートにも注記されます）。
