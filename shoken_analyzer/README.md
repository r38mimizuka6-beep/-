# 新店 低温カテゴリー予測ツール（shoken_analyzer）

新店の商圏データから、**低温ディビジョン**（和日配・洋日配・フローズン・精肉・パン）の
**粗利率・PI値・顧客層（年代別）**を予測し、根拠と実測精度つきでレポートを出します。
開店後は週次IDPOSを足していくことで、予測の答え合わせと精度向上ができます。

---

## このツールの立場（最初に読んでください）

**「商圏→PI・粗利率」の予測モデルは作っていません。**
既存店が5店なのに対して商圏変数は数十あるため、回帰でもGBMでも必ず過学習します。
**週次IDPOSが何十週あってもこれは変わりません。週を増やしても店舗数は増えないからです。**

出している数値は「類似店の実績の加重平均」です。そのかわり次の2つを必ず併記します。

1. **LOO検証による実測精度** — 既存店を1店ずつ「新店だと思って」残りから予測し、
   実際にどれだけ外れたかを測ります。レポートの「±X%」はすべてこの実測誤差です。
   同時に「全店平均で済ませた場合」とも比較し、
   **類似店法に意味があるのかどうか自体を出します**（意味がなければそう書きます）。
2. **週次変動から見た精度の上限** — 同じ店の同じカテゴリーが週ごとに何%振れるか。
   LOO誤差がこれを下回ることは原理的にありません。

## 入力

### (1) 商圏マスタ

```bash
python run_report.py template --out data/templates
```

`01_store_master.csv`（既存店）と `02_new_store.csv`（新店1行）。
**`store_id` は IDPOS の「店舗CD」と完全に一致させてください（先頭ゼロ含む）。**

商圏レポートExcel（1店舗=1ブック）があれば、商圏の人に関する約30項目は自動で埋まります。

```bash
python run_report.py extract --xlsx 商圏/*.xlsx --out data/master_auto.csv
```

### (2) 検索で埋める項目（競合・周辺施設・アクセス・自店）

商圏レポートのファイル名が店舗名になっているので、そこから調査メモを作れます。

```bash
python run_report.py search-plan --xlsx 商圏/*.xlsx --out data/search
```

- `search_brief.md` — 店舗ごとに「何をどう調べるか」と、そのまま貼れる検索クエリ
- `search_profile.csv` — 調べた結果を書き込むひな形

書き込んだら `report --search data/search/search_profile.csv` で渡します。
空欄のままでも動きます（その項目は類似度・範囲チェックから外れます）。

### (3) 週次IDPOS（2ファイル）

システムのエクスポートをそのまま渡せます。

| ファイル | 中身 |
|---|---|
| `IDPOS_*.csv` | 年週 × 店舗 × 階層 × 顧客種類 × 年代 → 売上税抜金額・PI値 |
| `URE_ZAIKO_*.csv` | 年週 × 店舗 × 階層 → 販売荒利高(千円)・販売荒利率 |

- 文字コード cp932、年週の表記ゆれ（`202640` と `2026年40週`）、
  `14.30%` のような率の文字列はすべて自動で処理します。
- 2ファイルは 年週 × 店舗CD × 階層 で突き合わせます。
- 列名・文字コードは `config/metrics.yaml` の `idpos` セクションで変更できます。

**会員の年代構成はIDPOSの行に入っているので、別ファイルは不要です。**
性別は実データに無いため使っていません。年代が「不明」の売上（非会員など）は
構成比の計算から外し、その割合をレポートに出します。

## レポートを出す

```bash
python run_report.py report \
    --master data/master.csv \
    --new    data/new_store.csv \
    --idpos  data/IDPOS_20261002.csv \
    --margin data/URE_ZAIKO_20261002.csv \
    --search data/search/search_profile.csv \
    --level  category \
    --out output/新店レポート.html \
    --excel output/新店レポート.xlsx
```

### 粒度（ドリルダウン）

`--level` で分析粒度を変えられます。階層は
**ディビジョン(低温) > ライン(和日配) > 部門 > カテゴリー(納豆) > サブカテゴリー**。

| 値 | 粒度 | 使いどころ |
|---|---|---|
| `line` | ライン | 和日配・洋日配など5つ。全体像 |
| `department` | 部門 | |
| `category` | カテゴリー | 納豆・豆腐・牛乳など。**提案の主粒度** |
| `subcategory` | サブカテゴリー | 小粒・ひきわりなど。最も具体的 |

レポートには**粒度ごとのLOO誤差と週次変動の比較表**が入ります。
粒度を下げるほど提案は具体的になりますが、1単位あたりの数字は小さく不安定になり、
5店舗ではどこかで当たらなくなります。**その境目を数字で確認してから粒度を決めてください。**

## レポートの中身

| 章 | 内容 |
|---|---|
| 1 | 新店の商圏（3軸での位置づけ、都市部／郊外判定）と類似店ランキング・選定理由 |
| 2 | **想定される粗利率・PI値**（予測値／区間／実測精度／根拠にした類似店） |
| 3 | **顧客層（年代別）** — 全体とカテゴリー別の主購買層 |
| 4 | **数字の根拠と正確性** — LOO検証、粒度別精度、範囲外チェック、商圏変数との関係 |
| 5 | **苦戦が予想されるカテゴリー** — 商売上のリスクと、判定自体の確からしさを分けて表示 |
| 6 | 開店後の答え合わせ手順とチェックリスト |

### 類似度の3軸

| 軸 | 内容 |
|---|---|
| 軸1 昼夜人口比 | 住宅地型 ⇔ オフィス・繁華街型 |
| 軸2 世帯構成 | 単身 ⇔ 子育て ⇔ 高齢 |
| 軸3 移動手段 | 徒歩・自転車 ⇔ 駅利用 ⇔ 車 |

重みは `--weight daynight=2.0` のように実行時に変えられます。
重みを変える前に、効果があるかを確認してください。

```bash
python run_report.py weights --master m.csv --idpos IDPOS.csv --margin URE.csv
```

誤差の地形が平坦なら、重みを変えても結果は変わりません（5店舗ではよくあります）。
差が出る場合でも、検証点は5店分しかないので、ここで最良の重みを選ぶこと自体が
過学習になり得ます。現場の感覚と合うものを選んでください。

### 顧客層の2つの推定方法

- **類似店ベース** — 類似店の年代構成をそのまま加重平均
- **商圏補正ベース** — 商圏の年齢構成 × 既存店に共通の「来店バイアス」

どちらが当たるかはLOO検証で測り、レポートに実測誤差（±Xpt）を出します。
2つが食い違う場合、その食い違い自体が不確実性の表示です。

### 「苦戦」の定義

商売上のリスク（水準が低い／商圏指標が範囲外／競合が重い／粗利貢献が小さい）だけで
判定します。**「予測が読めない」ことは苦戦ではない**ので、別列の
「判定の確からしさ」に分けています。確からしさ「低」のものは、
判定そのものが当てになりません。

## 開店後の答え合わせと精度向上

レポート作成時に予測が `output/predictions_<店舗CD>.json` に保存されます。
新店の週次IDPOSがたまったら：

```bash
python run_report.py verify \
    --prediction output/predictions_0199.json \
    --idpos      新店IDPOS.csv --margin 新店URE_ZAIKO.csv \
    --ref-idpos  既存IDPOS.csv --ref-margin 既存URE_ZAIKO.csv \
    --out output/verify.html
```

比較のときに次の2つを自動で補正します。

1. **開店効果** — 最初の2週はご祝儀需要が乗るので判定から除外します
2. **季節性** — 開店月の実績を、既存店の同じ月の季節指数で補正してから比較します

判定は4段階です。

| 判定 | 意味 |
|---|---|
| 想定内 | 予測区間に収まっている |
| ブレの範囲 | 区間外だが、その週数なら週次のブレで説明できる。週を足せば確定する |
| 上振れ／下振れ | 週次のブレでは説明できない。要因を切り分ける |
| 判定保留 | 週数が足りない（既定4週未満） |

**毎週データを足して再実行するほど「ブレの範囲」が狭まり、判定が確定していきます。**

### 精度を上げる順序

1. 検索データ（競合・周辺施設・来店手段）を埋める — 類似店の選定が変わります
2. 新店が26週たまったら、既存店マスタに**6店目として追加**する —
   LOOの検証点が5→6に増えます。郊外店が1店しかない問題も、郊外に出すたびに解消します
3. 商圏指標が範囲外だったカテゴリーの実績を確認し、ルールを見直す

## 既知の制約

- 既存店が5店である限り、本ツールの予測は仮説です。有意性の検定はしていません。
- 週次IDPOSを増やしても店舗数は増えないため、この制約は解消しません。
  解消するのは店舗を追加したときだけです。
- 郊外店が1店のみのため、新店が郊外寄りの場合は根拠が特に弱くなります。
- IDPOSに居住地が紐づいていないため、「商圏外からの来店」と「商圏内で来ていない層」は
  分離できません。来店バイアスの数値にはこの2つが混ざっています。
- 商圏定義（自転車10分圏など）が店舗間で揃っていないと、距離計算は意味を持ちません。
- PI値が金額ベースか数量ベースかで粗利PIの意味が変わります。
  `config/metrics.yaml` の `idpos.pi_kind` で切り替えてください（既定は金額ベース）。
